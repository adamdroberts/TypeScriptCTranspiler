# TODO — remaining work

Scope of the full project (from the approved plan): **full ECMAScript 2026 + transpile arbitrary `node_modules`**. At the current pace, what's done is roughly 65–75% of the 15-phase plan. The rest is measured in weeks and months, not hours.

Items are grouped by how soon they unblock the most user value. Within each group the ordering reflects dependency + estimated effort.

## 5. AOT closure requirements

These are not permanent product limits, but every reachable module, native bridge, and runtime-compiled source must be closed over at build time. `tsc2c` should keep rejecting cases it cannot prove or list ahead of time.

- **Runtime code compilation.** Constant `eval(...)` expressions and constant-body `Function(...)` / `new Function(...)` calls compile AOT without `--unsafe-eval`, including earlier local static `const` string aliases, single-valued template-literal type aliases, local const string maps/arrays, numeric literal array indexes, and forms with static parameter-name strings before the final body argument. Function parameter-name strings accept static literals, earlier local static `const` aliases, and single-valued template-literal type aliases. Manifest-listed non-constant eval expressions and function bodies dispatch over the compile-time allow-list, whose entries may be arrays or named object maps; function manifest dispatch uses the final body argument when earlier parameter-name strings, including earlier local static `const` aliases, are static. Unknown source strings still require the gated embedded-Node bridge behind `--unsafe-eval`.
- **Dynamic `require(...)`.** Finite static proofs, including earlier local static `const` string aliases, local variables annotated with inline or type-aliased string-literal union types or finite template-literal string types with string, numeric, bigint, boolean, null, or undefined literal placeholders, local const string maps/arrays with numeric literal array indexes, and local const maps with computed static keys, plus `--dynamic-require-manifest` allow lists compile every listed relative or package specifier into the AOT module graph. Manifest `requires` entries may be either an array or a named object map, and unlisted non-finite require sites still reject.
- **Native C++ addons under `node_modules/*/build/Release/*.node`.** Literal native addon specifiers and native-addon packages can now be security allow-listed through a compile-time native-addon manifest, which lowers known `require(...)`/import bindings to `runtime/tsc_node_embed.cc` via `tsc_node_native_addon(<manifest path>)` and links `libnode`. Package `exports` / `imports` condition maps, package-private `#...` imports, and package-private imports that target external native-addon packages are included in the native-addon closure checks, direct `.node` default imports are typed as `any` for manifest-backed bridge imports, and `bun run test:native-addon-smoke` validates a real N-API addon path when `libnode` is available. Manifest-backed package-private imports to external native-addon packages lower through the embedded Node bridge. Unlisted native addons still reject.
