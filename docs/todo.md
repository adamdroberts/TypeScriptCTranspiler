# TODO — remaining work

Scope of the full project (from the approved plan): **full ECMAScript 2026 + transpile arbitrary `node_modules`**. At the current pace, what's done is roughly 65–75% of the 15-phase plan. The rest is measured in weeks and months, not hours.

Items are grouped by how soon they unblock the most user value. Within each group the ordering reflects dependency + estimated effort.

## 2. Medium-term phases (weeks each)

- **Phase 6 — `async`/`await` + libuv event loop** (~3 weeks)
  - Settled/immediate `Promise<T>` values are implemented for `Promise.resolve(value)`, `Promise.reject(reason)`, synchronous `.then(...)`, `.catch(...)`, `.finally(...)`, and settled-array `Promise.all`/`allSettled`/`race`/`any` over compiler-known callbacks and promise arrays. Test: `promise_settled`
  - `new Promise<T>(executor)` now supports an immediate/synchronous subset: the executor is called once, generated `resolve` / `reject` callbacks settle at most once, executor throws become rejections unless already settled, and executors that do not settle return a pending promise. Test: `promise_executor`
  - `Promise.resolve(existingPromise)` now adopts an existing native Promise record, preserving fulfilled, rejected, and pending state. Test: `promise_resolve_adopt`
  - `Promise.try(callback)` is implemented for immediate callbacks, fulfilling from returned values and rejecting from thrown values. Test: `promise_try`
  - `Promise.prototype.then()` now accepts an omitted fulfillment handler and `.then(undefined, onRejected)` in the immediate subset, passing fulfilled values through while preserving rejection handling. Test: `promise_then_passthrough`
  - `Promise.prototype.catch()` and `.finally()` now accept omitted or `undefined` handlers in the immediate subset, preserving fulfilled, rejected, and pending state. Test: `promise_empty_handlers`
  - Immediate Promise callbacks and `Promise.try(callback)` now adopt returned native Promise records instead of boxing them as fulfillment values. Test: `promise_callback_adopt`
  - Immediate `.finally()` callbacks now adopt returned native Promise records for rejected and pending outcomes while preserving the original promise state after fulfilled returned promises. Test: `promise_finally_adopt`
  - Immediate `.then` / `.catch` / `.finally` callback throws now become rejected Promise records in the same synchronous subset. Test: `promise_callback_throw`
  - Top-level `async function` declarations, class `async` methods, and async function values without `await` return immediate Promise records: returned values fulfill, returned native Promise records are adopted, implicit returns fulfill with `undefined`, and synchronous uncaught throws reject. Tests: `async_function_immediate`, `async_methods_immediate`, `async_function_values_immediate`, `async_throw_rejection`
  - Immediate `await` over native Promise records and non-Promise values is implemented inside the current async subset: fulfilled awaits unwrap values, non-Promise awaits evaluate once and continue with that value, rejected awaits return rejected Promise records, and pending awaits return pending Promise records without scheduling a continuation. Tests: `async_await_immediate`, `async_await_values_immediate`
  - Local `try`/`catch` inside the immediate async subset catches rejected native Promise records from `await`; uncaught awaited rejections still return rejected Promise records. Test: `async_await_try_catch`
  - Full state-machine lowering of each `async` function remains deferred. A real `await` must become a suspend/resume point that chains a `.then` onto the awaited promise.
  - `Promise.any` now rejects with an AggregateError-shaped dynamic object containing `name`, `message`, and `errors` when every input rejects, including empty input. Test: `promise_any_aggregate`
  - Empty `Promise.race([])` now returns a pending promise whose chained `.then` / `.catch` / `.finally` callbacks are not synchronously invoked. Test: `promise_race_empty_pending`
  - Pending records now propagate through immediate `Promise.all` / `allSettled` / `race` / `any` without synchronously invoking chained callbacks. Test: `promise_pending_combinators`
  - Still missing: suspend/resume `await` state-machine lowering, microtask-scheduled `.then` dispatch, arbitrary thenable assimilation, and full async function edge cases.
  - Full Promise microtask scheduling plus full `process.nextTick` scheduling remains; a bounded `process.nextTick(callback, ...args)` queue is implemented for up to three typed callback arguments, a bounded `queueMicrotask(callback)` queue is implemented for zero-argument callbacks drained after next ticks, a bounded zero-delay `setTimeout(callback, 0, ...args)` queue is implemented for up to three typed callback arguments drained after next ticks and microtasks, and a bounded `setImmediate(callback, ...args)` queue is implemented for up to three typed callback arguments drained after next ticks, microtasks, and zero-delay timeouts before program exit. Tests: `queue_microtask`, `set_timeout_zero`, `set_immediate`
  - libuv (`libuv1-dev`) bound for nonzero-delay `setTimeout`, `setInterval`, real event-loop-backed `setImmediate`, and all future async I/O.

## 5. Permanent limits (will never be done)

These are genuinely impossible to AOT-compile at any engineering investment. The plan documents them, and `tsc2c` emits hard errors for the limits it can see before emission.

- **Native C++ addons under `node_modules/*/build/Release/*.node`.** They're compiled against Node's V8 ABI and the embedder's internals. We can't transpile their source because we don't have it — they're binary `.node` files. Literal `.node` import/require specifiers and literal package imports/requires whose installed package root contains `build/Release/*.node` are rejected now, including transitive imports from emitted package sources under `node_modules`; broader package export/condition handling remains Phase 14. Suggested workaround is to document pure-JS alternatives.
- **Runtime code compilation** — JavaScript offers two constructs that require compiling source text at runtime. `tsc2c` is ahead-of-time and has no compiler in the produced binary, so `eval`, `Function(...)`, and `new Function(...)` are rejected before TypeScript diagnostics.
- **Dynamic `require(variable)`** where the argument isn't a string literal. The import graph is walked statically; a variable-valued specifier is unknowable at compile time, so non-literal `require(...)` is rejected before emission.

## How to pick

If the next session has **hours**, pick from section 4 (smaller pieces).

If it has **a few days to a week**, pick a bounded item from section 2, such as generator-backed iterables, unless the session is large enough to start Phase 3.

If it has **a week or more** to invest in one thing, do **Phase 3 (NaN-boxing)** from section 1. That one item unblocks about half of what's in sections 2–4.

If the goal is **"run a real npm package"**, the sequential chain is: Phase 3 → Closures → Phase 6 → Phase 14. Expect roughly two months of focused work for that end-to-end.
