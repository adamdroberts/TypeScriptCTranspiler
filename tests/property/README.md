# Property evidence

Add compact semantic-partition specifications as `*.property.test.ts`. `run.ts` discovers every such file recursively and fails when none exist, so an empty suite cannot satisfy the ECMAScript claim gate.

Each terminal matrix partition must reference the exact property specification that exercises its canonical collection, tree, graph, or worklist. An authored finite/unbounded label never changes that obligation. Property evidence is distinct from the generated representative stress cases under `tests/e2e/cases/`.

`async-cfg.property.test.ts` is the first architectural specification: it generates recursive combinations of statement and expression partitions, independently reconstructs the returned edge graph, and checks closure, reachability, one suspension owner per source `await`, and fail-closed rejection. It establishes the property gate itself; it is not clause evidence until an exact terminal clause partition reciprocally registers it with distinct stress and implementation evidence.

`call-activation.property.test.ts` generates JavaScript formal/actual argument plans and independently models expected argument counts, default initialization, mapped versus unmapped parameter writes, excess arguments, abrupt nested calls, lexical arrow access, and mutation through the activation's actual dynamic storage type even when JSDoc control-flow narrowing exposes a static view. One representative wide input exercises the same activation worklist as a stress guard; its size is not used as completion evidence.

`array-representation.property.test.ts` derives compatible typed/dynamic alias mutations from one operation worklist and independently models identity, writes, deletion, reversal, holes, key order, and primitive element boxing. One representative wide operation collection guards the same per-array codec path against fixed-shape lowering; its width is not completion evidence.

`object-intrinsic-alias.property.test.ts` generates descriptor plans and independently checks their flags, keys, bound-call forwarding, primitive wrappers, and dynamic-array representation under a narrowed `string[]` source view. One representative wide descriptor collection exercises the same key worklist; its size is not completion evidence.

`script-global-binding.property.test.ts` generates Script binding and Reference plans and independently checks bidirectional identifier/property reflection, descriptors, declaration instantiation, strict/sloppy `PutValue`, rejected writes, updates, deletion, evaluation order, lexical non-reflection, and function `this` normalization against one canonical global-object environment. One representative deeply nested statement combines declaration and unresolved-reference writes through the same source-tree and Reference algorithms; its depth is not completion evidence. This remains architectural evidence until exact terminal clause partitions reciprocally register distinct implementation, generated-regression, stress, and E2E artifacts.

`strict-equality.property.test.ts` derives comparisons from one canonical collection of ECMAScript language Types and independently applies the Strict Equality algorithm. The generated program verifies every represented Type pairing, identity/value partitions, `NaN`, signed zero, negation, pointer-backed single-nullish unions versus boxed dual-nullish unions, left-to-right operand evaluation, and left/right abrupt-completion propagation with exact thrown-value identity in both runtime memory modes; individual pair counts are not completion evidence.

`dynamic-primitive.property.test.ts` derives BigInt and Symbol probes from one semantic collection after both values cross the canonical dynamic representation boundary. It independently checks type, truthiness, value versus identity equality, explicit string conversion, primitive and wrapper branding, prototype selection, wrapper extraction, hash-key behavior, the BigInt arithmetic/bitwise/shift/update/relational and mixed-Type error partitions, and survival across forced collection in both runtime memory modes; the probe inventory is a partition specification, not a coverage denominator.

`symbol-coercion.property.test.ts` treats the pinned well-known Symbol names as one canonical semantic collection and independently checks identity, descriptions, constructor descriptors, prototype intrinsics, primitive wrappers, `@@toPrimitive` hints/fallback/error/abrupt partitions, and `ToPropertyKey` across string- and Symbol-valued results. Its computed-key mutation sequence also verifies left-to-right string-concatenation evaluation; the representative collection is architectural evidence, never an aggregate coverage denominator.

`mutable-function-binding.property.test.ts` derives arrow, ordinary-function, null, and undefined writes from one canonical binding worklist and independently models every observation. The same worklist crosses module/script lexical storage and a closure-captured local in both runtime memory modes; its representative stress tail guards the shared storage decision without making write count a coverage measure.

`html-dda.property.test.ts` derives the Test262 host-global, hidden `%AbstractModuleSource%`, and normative Annex B `[[IsHTMLDDA]]` behavior from one semantic-probe collection. It independently checks `$262`/`print` global identity and descriptors, every abstract-module-source intrinsic/prototype partition, and the callable exotic object's `typeof`, truthiness, abstract/strict/SameValue equality, nullish behavior, and required call results in both runtime memory modes; the probe inventory is a partition specification, not a coverage denominator.
